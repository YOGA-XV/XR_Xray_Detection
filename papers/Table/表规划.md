下面按你前面规划的 **正文 8 张表**逐一详细说明。目标是让你可以直接开始建 Excel / Markdown / LaTeX 表格，并知道每张表该放什么、不该放什么、怎么解释。

我先给总原则：

```text
表格负责给证据，图负责讲故事。

表格不要追求“多”，而要追求：
1. 每张表都有明确论证目的；
2. 指标统一；
3. 对比公平；
4. 能直接支撑论文贡献点；
5. 数字不能堆得乱。
```

------

# Table 1 Dataset Statistics

## 表名

**Table 1. Statistics of the X-ray security datasets.**

中文理解：

> 数据集统计表。

------

## 这张表的作用

这张表放在 **Experiments → Datasets and Metrics** 里，用来说明你用了哪些数据集，以及这些数据集为什么能支撑你的论文主张。

它要回答：

1. 你的实验用了哪些数据集；
2. 每个数据集有多少图像、多少类别、多少目标实例；
3. 是否包含小目标、细长目标、遮挡目标、隐藏目标；
4. 是否有难度划分；
5. 是否适合验证你的方法。

------

## 建议列设计

推荐表头：

| Dataset | #Images | #Classes | #Instances | Train / Val / Test | Small Obj. Ratio | Thin Obj. Ratio | Occlusion Annotation | Difficulty Split |
| ------- | ------- | -------- | ---------- | ------------------ | ---------------- | --------------- | -------------------- | ---------------- |
|         |         |          |            |                    |                  |                 |                      |                  |

------

## 每一列解释

### Dataset

填写数据集名称。

例如：

```text
SPXray
PIDray
OPIXray
```

如果你最终还用 SIXray，也可以加。

------

### #Images

数据集图像总数。

注意：

如果你只使用了其中一个子集，不能写完整数据集总数，要写你实际使用的数量。

例如：

```text
12,000
47,677
8,885
```

具体数字以你的实际数据统计为准。

------

### #Classes

类别数。

例如：

```text
5
10
12
```

必须和你的训练配置一致。

------

### #Instances

标注框数量。

这个指标很重要，因为目标检测不是只看图像数量，还要看目标实例数量。

建议用你自己的统计脚本统计：

```text
Total bounding boxes
```

------

### Train / Val / Test

写数据划分。

例如：

```text
7,000 / 2,000 / 3,000
```

或者：

```text
Official split
```

如果你自己划分，要写清楚：

```text
8:1:1 random split
```

但更推荐使用官方划分。

------

### Small Obj. Ratio

小目标比例。

建议定义为：

```text
area(box) / area(image) < threshold
```

例如按照 COCO 小目标定义：

```text
area < 32² pixels
```

但因为 X-ray 图像分辨率可能不同，你也可以用归一化面积定义：

```text
box_area / image_area < 0.01
```

关键是：**定义必须在正文里写清楚。**

表中可以写：

```text
23.4%
```

------

### Thin Obj. Ratio

细长目标比例。

建议定义为：

```text
aspect ratio = max(w/h, h/w)
thin object if aspect ratio > 3
```

或者更严格：

```text
aspect ratio > 5
```

建议你用：

```text
AR > 3
```

因为安检图像里剪刀、刀具这类目标经常细长，但未必都超过 5。

表中写：

```text
18.7%
```

------

### Occlusion Annotation

写是否有遮挡标注。

可能取值：

```text
Yes
No
Partial
```

如果 SPXray 没有显式 hidden 标注，你不能写 Yes。可以写：

```text
Overlap estimated by bbox IoU
```

或者：

```text
No explicit annotation
```

这点很重要。不能把你自己计算的 overlap 子集说成官方 hidden 标注。

------

### Difficulty Split

写数据集是否有难度划分。

例如：

```text
Easy / Hard / Hidden
Light / Medium / Heavy
None
```

PIDray 如果使用 Easy / Hard / Hidden，就写进去。OPIXray 如果有遮挡等级，就写：

```text
Occlusion levels
```

------

## 推荐表格示例模板

```text
Table 1. Statistics of the X-ray security datasets.

Dataset | #Images | #Classes | #Instances | Train / Val / Test | Small Obj. Ratio | Thin Obj. Ratio | Occlusion Annotation | Difficulty Split
SPXray  | ...     | ...      | ...        | ...                | ...              | ...             | Overlap by bbox IoU  | None
PIDray  | ...     | ...      | ...        | Official split     | ...              | ...             | Hidden annotation    | Easy / Hard / Hidden
OPIXray | ...     | ...      | ...        | Official split     | ...              | ...             | Occlusion annotation | Light / Medium / Heavy
```

------

## 表下注释建议

表下注释可以写：

```text
Small objects are defined according to normalized bounding-box area. Thin objects are defined as objects with aspect ratio larger than 3. For datasets without explicit occlusion labels, overlap subsets are constructed based on bounding-box IoU.
```

中文意思：

> 小目标根据归一化框面积定义，细长目标根据长宽比定义。没有官方遮挡标注的数据集，用 bbox IoU 构造 overlap 子集。

------

## 常见错误

不要犯这些错误：

1. 不要写你没有实际使用的数据集数量；
2. 不要把 overlap 子集写成 hidden 子集；
3. 不要不说明 small / thin 的定义；
4. 不要只写图像数，不写实例数；
5. 不要把训练集、验证集、测试集混在一起统计。

# Table 2 Main Results on SPXray

## 表名

**Table 2. Main comparison results on SPXray.**

中文理解：

> SPXray 主结果对比表。

------

## 这张表的作用

这是你论文的第一张核心实验表。

它要回答：

1. 你的方法在主数据集 SPXray 上是否有效；
2. 相比 YOLOv8n、YOLOv8s 等基线是否有优势；
3. 性能提升是否依赖更大模型；
4. 精度、速度、参数量之间的权衡如何。

------

## 建议列设计

推荐表头：

| Method | Backbone | Input | Aug. | Params (M) | FLOPs (G) | FPS  | P    | R    | mAP50 | mAP50:95 |
| ------ | -------- | ----- | ---- | ---------- | --------- | ---- | ---- | ---- | ----- | -------- |
|        |          |       |      |            |           |      |      |      |       |          |

如果表太宽，可以简化为：

| Method | Input | Aug. | Params | FLOPs | FPS  | mAP50 | mAP50:95 |
| ------ | ----- | ---- | ------ | ----- | ---- | ----- | -------- |
|        |       |      |        |       |      |       |          |

------

## 建议方法行

建议至少包含：

```text
YOLOv8n
YOLOv8s
YOLO11n
RT-DETR-R18
YOLOv8n + PCN
YOLOv8n + EGI
YOLOv8n + PCN + EGI
EOA-YOLO
```

如果版面允许，可以加入：

```text
YOLOv10n
YOLOv9-t
Faster R-CNN
DETR / Deformable DETR
```

但不要放太多无关方法。你的论文重点是轻量 X-ray 检测，所以主对比应围绕轻量检测器。

------

## 每一列解释

### Method

方法名称。

建议统一命名：

```text
YOLOv8n
YOLOv8s
YOLO11n
RT-DETR-R18
PCN+EGI
EOA-YOLO
```

不要一会写 `Ours-Lite`，一会写 `XR-Lite`，一会写 `A3`。论文里方法名必须统一。

------

### Backbone

写主干。

例如：

```text
CSPDarknet-like
YOLOv8n
YOLOv8s
ResNet-18
```

如果嫌复杂，可以省略这一列。

------

### Input

写输入形式。

例如：

```text
RGB
PCN-RGB
RGB+Edge
PCN-RGB+Edge
```

你的方法应该写：

```text
PCN-RGB+Edge
```

------

### Aug.

写训练增强。

例如：

```text
Default
MixUp
Copy-Paste
BLT-Mix
```

EOA-YOLO 写：

```text
BLT-Mix
```

PCN+EGI 不加 BLT-Mix 时写：

```text
Default
```

------

### Params

模型参数量，单位 M。

例如：

```text
3.2
11.2
```

注意：
PCN 和 Scharr Edge 是否计入参数？

它们没有可学习参数，所以 Params 不会明显增加。你可以在表下注明：

```text
PCN and Scharr edge extraction introduce no learnable parameters.
```

------

### FLOPs

浮点计算量，单位 G。

注意：

1. 是否包括 PCN 和 Scharr 预处理；
2. 是否只统计模型前向；
3. 是否所有方法输入尺寸一致。

建议你在正文说明：

```text
FLOPs are measured at 640×640 input resolution.
```

------

### FPS

速度。

必须统一硬件。

例如：

```text
FPS measured on RTX 4090 with batch size 1.
```

或者：

```text
Latency measured on NVIDIA RTX 3090, batch size 1.
```

建议你同时记录：

```text
FPS
Latency
```

但正文表可以只放 FPS，附录放 latency。

------

### P / R

Precision 和 Recall。

如果表太宽，可以不放 P，只放 Recall。因为你的任务里漏检很重要，Recall 更有价值。

------

### mAP50

常见目标检测指标。

------

### mAP50:95

最重要主指标。

建议用加粗标出最佳结果：

```text
0.8123
```

用下划线标出第二好结果。

------

## 推荐分组方式

为了清楚，可以把方法分成三组：

```text
Generic detectors
X-ray-oriented variants
Ours
```

表格里用横线分隔：

```text
YOLOv8n
YOLOv8s
YOLO11n
RT-DETR-R18
-----------------------
YOLOv8n + PCN
YOLOv8n + EGI
YOLOv8n + PCN + EGI
-----------------------
EOA-YOLO
```

------

## 表下注释建议

```text
All methods are trained under the same input resolution and training schedule. FPS is measured with batch size 1 on the same GPU. The best result is highlighted in bold, and the second best is underlined.
```

------

## 这张表的理想结论

你希望能写：

```text
EOA-YOLO achieves better mAP50:95 than YOLOv8n while maintaining a comparable parameter size and inference speed. Compared with YOLOv8s, EOA-YOLO provides a better accuracy-efficiency trade-off.
```

如果总体 mAP 提升不大，就不要硬写大幅提升。可以写：

```text
Although the overall mAP improvement is moderate, EOA-YOLO preserves lightweight inference and provides stronger robustness on difficult cases, as shown later.
```

------

## 常见错误

1. 不要拿不同输入尺寸的方法比较；
2. 不要拿不同 epoch 的结果比较；
3. 不要只报最优 seed，不报平均；
4. 不要把 YOLOv8s 的高精度说成不公平，除非你解释参数/FLOPs；
5. 不要隐藏 Ours 不如某个强基线的事实。

# Table 3 Main Results on PIDray

**Table 3. Comparison results on PIDray under different difficulty levels.**

中文理解：

> PIDray 不同难度子集上的结果对比表。

------

## 这张表的作用

这张表比 SPXray 主表更重要，因为它验证你的方法是否能泛化到公开大规模真实数据集，特别是 Hidden 场景。

它要回答：

1. 方法是否只在你自己的 SPXray 上有效；
2. 在 PIDray Easy / Hard / Hidden 上是否有效；
3. 是否真的提升隐藏违禁品检测；
4. BLT-Mix 是否对 hidden 场景有价值。

------

## 建议列设计

推荐表头：

| Method | Params (M) | FPS  | Easy mAP50:95 | Hard mAP50:95 | Hidden mAP50:95 | Overall mAP50:95 | Hidden Recall |
| ------ | ---------- | ---- | ------------- | ------------- | --------------- | ---------------- | ------------- |

如果你想更详细：

| Method | Easy mAP50 | Easy mAP50:95 | Hard mAP50 | Hard mAP50:95 | Hidden mAP50 | Hidden mAP50:95 | Overall |
| ------ | ---------- | ------------- | ---------- | ------------- | ------------ | --------------- | ------- |
|        |            |               |            |               |              |                 |         |

但表会很宽。建议正文用简洁版，附录放详细版。

------

## 建议方法行

至少包含：

```text
YOLOv8n
YOLOv8s
YOLO11n
RT-DETR-R18
PCN + EGI
PCN + EGI + Copy-Paste
EOA-YOLO
```

为什么要加 `PCN + EGI + Copy-Paste`？

因为它能证明：

```text
BLT-Mix 的收益不是普通遮挡增强都能带来的。
```

------

## 每一列解释

### Easy mAP50:95

普通场景表现。

如果你的方法在 Easy 上提升不大，这是可以接受的。

------

### Hard mAP50:95

困难样本表现。

这里希望 EOA-YOLO 有提升。

------

### Hidden mAP50:95

核心列。

你的论文强调 hidden / occluded prohibited items，所以这列非常关键。

如果 EOA-YOLO 在 Hidden 上没有提升，BLT-Mix 的主张会变弱。

------

### Overall mAP50:95

整体表现。

这列不能没有，否则审稿人会质疑你只挑难例。

------

### Hidden Recall

建议加上。

安检任务中漏检比误检更严重。Recall 能体现方法是否减少漏检。

如果表太宽，Hidden Recall 可以放到附录；但我建议正文保留。

------

## 推荐表格示例

```text

PCN + EGI + Copy-Paste | ... | ... | ... | ... | ... | ... | ...
EOA-YOLO | ... | ... | ... | ... | ... | ... | ...
```

------

## 表下注释建议

```text
PIDray is evaluated under its difficulty subsets. Hidden Recall is reported to reflect the ability to detect deliberately hidden prohibited items.
```

------

## 这张表的理想结论

你希望看到：

```text
EOA-YOLO 在 Hidden 上提升最大；
Hard 次之；
Easy 提升较小。
```

这说明你的方法不是简单提高普通样本，而是针对困难场景有效。

可以在论文里写：

```text
The performance gain is more pronounced on the Hidden subset, indicating that BLT-Mix improves the detector's robustness to concealed prohibited items.
```

------

## 常见错误

1. 不要只报 Overall，不报 Easy/Hard/Hidden；
2. 不要把 PIDray 子集混合训练和分开测试说不清；
3. 不要只在 Hidden 上调参，然后拿 Easy/Hard 比；
4. 不要不报 Recall；
5. 不要把 Hidden 当成你自己构造的 overlap。

## 每一列解释

### Light

轻遮挡子集。

这里提升可能较小。

------

### Medium

中等遮挡子集。

希望方法有明显提升。

重遮挡子集。

```text

```

### FLOPs / FPS

说明输入预处理开销是否可接受。

------

```text
AP-overlap is computed on samples where the target overlaps with other objects.
```


------

## 这张表的论文写法

如果结果好，可以写：

```text
EGI provides consistent gains on AP-thin, suggesting that explicit edge cues help the detector capture thin prohibited items. PCN further improves overall performance by reducing pseudo-color distribution variation. Combining PCN and EGI achieves the best trade-off.
```

如果 PCN 单独不明显，但组合有效，可以写：

```text
Although PCN alone provides limited improvement, it complements EGI by stabilizing the pseudo-color distribution before edge extraction.
```

------

## 常见错误

1. 不要只报 mAP，不报 AP-thin；
2. 不要把 PCN + EGI 和 BLT-Mix 混在一起做这张表；
3. 不要把所有模块都塞进 Table 5；
4. 不要不说明 AP-overlap 定义；
5. 不要只跑一个 seed 就下结论。

普通梯度边缘。

------

你的默认方法。

经典边缘检测。

二阶边缘。

------

可学习边缘分支。

```text
AP-thin
AP-small
FPS
Extra Params
```

因为边缘算子的目标是增强细长结构和轮廓，而不是单纯刷总 mAP。


```text
Scharr achieves the best accuracy-efficiency trade-off, especially on thin prohibited items.
```


# 表格统一格式建议

## 数字保留位数

建议：

```text
mAP / AP / Recall：保留 3 位小数，或百分制保留 1 位小数
Params：保留 2 位
FLOPs：保留 1 或 2 位
FPS：保留 1 位
Latency：保留 2 位 ms
```

例如：

```text
0.792
79.2
3.16M
8.7G
214.5 FPS
4.66 ms
```

全文必须统一，不要一张表用 0.792，一张表用 79.2%。

------

## 推荐使用百分制还是小数制

目标检测论文中两种都可以。
我建议你用百分制，更直观：

```text
mAP50:95 = 79.2
```

而不是：

```text
0.792
```

但如果你的实验日志默认是 0.792，也可以用小数。关键是全文统一。

------

## 最佳和次优标记

建议：

```text
Best：bold
Second best：underline
```

例如：

```text
\textbf{80.3}
\underline{79.8}
```

不要用颜色标最佳，黑白打印可能看不清。

------

## 是否报告 mean ± std

高质量论文建议主结果表报告：

```text
mean ± std
```

例如：

```text
79.2 ± 0.3
```

但表会变宽。

折中方案：

正文主表写 mean：

```text
79.2
```

表注说明：

```text
All reported results are averaged over three random seeds.
```

然后附录给 mean ± std。

如果你的结果波动较大，正文最好直接写：

```text
79.2 ± 0.3
```
