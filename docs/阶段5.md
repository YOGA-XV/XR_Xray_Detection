# 阶段5：YOLOv8n-XR-Plus 结构准备记录

## 1. 重要修正

我之前把阶段5的 Plus 版本理解成：

```text
A3 + P2-Lite
```

这个理解不完整。

按照 `完整版试验设计方案.md` 和 `模型体系设计方案.md`，阶段5真正要准备的 Plus 版本应为：

```text
YOLOv8n-XR-Plus = A3 + EMA-Lite + AIFI-Lite + P2-Lite
```

其中：

```text
A3 = PCN + EGI
EMA-Lite = 轻量注意力增强
AIFI-Lite = 轻量全局上下文增强
P2-Lite = 小目标高分辨率检测头
```

因此，阶段5的正式主实验不是单独的 `A3 + P2-Lite`，而是完整的：

```text
PCN + EGI + EMA-Lite + AIFI-Lite + P2-Lite
```

原先新增的 `yolov8n-xr-p2lite.yaml` 仍然可以保留，但它只适合作为 **P2-only 辅助消融**，不能代表 Plus 版本。

## 4. YOLOv8n-XR-Plus 结构说明

Plus 版本结构主体如下：

```text
Input:
  4-channel image
  RGB/gray content + PCN/EGI related channel behavior由数据管线控制

Backbone:
  YOLOv8n backbone
  P4位置加入 C2fEMALite
  P5上下文位置使用 SPPFAIFILite

Neck:
  保留 YOLOv8n P3/P4/P5 PAN-FPN 主路径
  P4/P5检测分支继续使用 C2fEMALite

P2-Lite Head:
  P3特征上采样
  与 backbone P2 特征拼接
  使用 DWConv + 1x1 Conv 轻量融合
  输出 P2/4 小目标检测特征

Detect:
  Detect(P2, P3, P4, P5)
```

最终检测尺度：

```text
P2: stride 4
P3: stride 8
P4: stride 16
P5: stride 32
```

## 5. 为什么仍然保留 P2-only YAML

阶段5正式 Plus 是：

```text
A3 + EMA-Lite + AIFI-Lite + P2-Lite
```

但保留 `A3 + P2-Lite` 仍然有价值，因为它可以作为拆解实验：

```text
A3                 : PCN + EGI
Stage4 Lite        : A3 + EMA-Lite + AIFI-Lite
P2-only auxiliary  : A3 + P2-Lite
Stage5 Plus        : A3 + EMA-Lite + AIFI-Lite + P2-Lite
```

这样后续分析时可以回答：

- P2-Lite 单独有没有提升 AP-small；
- EMA/AIFI 单独有没有提升；
- EMA/AIFI 与 P2-Lite 叠加后是否有互补收益；
- 如果 Plus 有提升，提升主要来自 P2，还是来自模块叠加。

## 9. 判定规则

### 9.1 保留 YOLOv8n-XR-Plus

如果 Plus 满足以下条件，可以保留为 Plus 版本：

- AP-small 相比 A3 或 Stage4 Lite 有明确提升；
- mAP50:95 不明显低于 A3；
- AP-thin 不明显低于 A3；
- FPS 下降在可接受范围内；
- 显存占用可接受。

### 9.2 Plus 只作为论文消融，不作为主推模型

如果 Plus 有小目标收益，但整体 mAP 或速度代价较大，可以作为论文中的增强版或消融版本，而不作为主推部署模型。

此时可以采用：

```text
Ours-Lite = A3 或 Stage4 Lite 中表现更好的版本
Ours-Plus = A3 + EMA-Lite + AIFI-Lite + P2-Lite
```

### 9.3 放弃 Plus

如果 Plus 出现以下情况，应放弃：

- AP-small 没有提升；
- mAP50:95 明显下降；
- AP-thin 明显下降；
- FPS 下降超过收益；
- 训练不稳定。

这种情况下，最终主线应回到 A3 或表现最稳的 Lite 版本。
