# 阶段2：PCN 与 EGI 输入体系实现记录

## 1. 阶段2目标

本阶段依据 `完整版试验设计方案.md`、`模型体系设计方案.md` 和已经补充过的 `项目实施步骤.md`，完成 YOLOv8n 输入侧增强实验的工程准备。

阶段2不直接跑 300 epoch 长训练，而是把 A1、A2、A3 三组实验所需的代码、配置、权重适配、推理开关和验证测试准备好，保证后续训练时可以严格按同一协议执行。

|---|---|---:|---|
| A0 | YOLOv8n baseline | 3 | 阶段1已有基准 |

## 2. 已完成的工程修改

### 2.1 新增 PCN 与 EGI 预处理模块

新增文件：

```text
ultralytics/data/xr_preprocess.py
```

实现内容：

1. `pseudo_color_normalize`
   - 按图像、按通道计算 P1/P99。
   - 将每个颜色通道裁剪并线性归一化到 0-255。
   - 输出仍为 `uint8`，保持与原 YOLOv8 图像管线兼容。
   - 对应 `项目实施步骤.md` 阶段2中 PCN 的固定定义。

2. `scharr_edge_map`
   - 使用 OpenCV BGR 图像计算灰度图。
   - 使用 Scharr X/Y 梯度。
   - 梯度幅值归一化为单通道 `uint8` 边缘图。
   - 对应 `模型体系设计方案.md` 中 EGI 的边缘增强输入思想。

3. `apply_xr_preprocess`
   - `use_pcn=False, use_egi=False`：保持原图。
   - `use_pcn=True, use_egi=False`：输出 3 通道 PCN 图像。
   - `use_pcn=False, use_egi=True`：输出 4 通道 raw RGB + Edge。
   - `use_pcn=True, use_egi=True`：输出 4 通道 PCN + Edge。

4. GPU tensor 版预处理
   - `pseudo_color_normalize_tensor`：在 BCHW tensor 上执行逐图、逐通道 P1/P99 归一化。
   - `scharr_edge_map_tensor`：在 BCHW RGB tensor 上使用 Scharr 卷积核生成 Edge 通道。
   - `apply_xr_preprocess_tensor`：在 batch 已经搬到 GPU 后执行 PCN/EGI。
   - 当前训练、验证、预测主路径使用 tensor 版，CPU 版保留为参考和 fallback。

### 2.2 接入训练/验证数据管线

修改文件：

```text
ultralytics/data/dataset.py
ultralytics/models/yolo/detect/train.py
ultralytics/models/yolo/detect/val.py
```

接入方式：

- `YOLODataset` 只负责读取图像、数据增强、letterbox 和转 tensor，不再在 CPU transform 中执行 PCN/EGI。
- batch 搬到 `self.device` 后，在 `DetectionTrainer.preprocess_batch()` 中读取数据 YAML 的 `xr_pcn` 和 `xr_egi`，再调用 `apply_xr_preprocess_tensor`。
- 验证阶段在 `DetectionValidator.preprocess()` 中使用相同逻辑。
- 因此 A1 的 batch 仍为 3 通道，A2/A3 会在 GPU 上追加 Edge 通道变成 4 通道。

### 2.3 修正 4 通道图像格式转换

修改文件：

```text
ultralytics/data/augment.py
```

原 YOLOv8 的 `Format._format_img` 默认只处理 3 通道 BGR->RGB。阶段2增加了 Edge 第四通道后，需要避免把 Edge 通道一起反转。

现在规则固定为：

- 3 通道：`BGR -> RGB`
- 4 通道或更多：前三通道 `BGR -> RGB`，额外通道保持原顺序

即训练侧输入顺序为：

```text
RGB + Edge
```

### 2.4 修正推理路径的 4 通道转换

修改文件：

```text
ultralytics/engine/predictor.py
```

推理侧也加入同样的规则：

- 先执行 letterbox 和 `BGR -> RGB`。
- 图像 tensor 搬到 `self.device` 并归一化到 0-1。
- `xr_pcn=True` 时在 GPU tensor 上执行 PCN。
- `xr_egi=True` 时在 GPU tensor 上追加 Edge 通道。

这一步很关键，否则会出现训练是 `RGB+Edge`，推理却是 `BGR+Edge` 的隐性不一致。

### 2.5 增加阶段2命令行/预测参数

修改文件：

```text
ultralytics/cfg/default.yaml
ultralytics/cfg/__init__.py
```

新增参数：

```yaml
xr_pcn: False
xr_egi: False
```

并将二者注册为 bool 参数。后续 `train`、`val`、`predict` 都可以识别这两个开关。

### 2.6 实现 4 通道首层卷积预训练权重适配

修改文件：

```text
ultralytics/nn/tasks.py
```

新增函数：

```text
adapt_input_conv_weight
```

适配策略：

- 当目标模型仍是 3 通道时，按原 YOLOv8 加载逻辑执行。
- 当目标模型为 4 通道时：
  - 前 3 个通道直接复制 COCO 预训练权重。
  - 第 4 个 Edge 通道用前三通道卷积核均值初始化。

该策略符合阶段2设计中“尽量保留 COCO 预训练收益，同时给 Edge 通道一个稳定初值”的原则。

## 7. 阶段2判断标准

优先比较 A1/A2/A3 与 A0 YOLOv8n：

```text
A0 YOLOv8n:
mAP50:95 = 0.78888
AP-small = 0.67436
AP-thin  = 0.84901
```

建议判断逻辑：

1. 如果 A1 提升 AP-small 或 AP-thin，说明 PCN 对 X 射线低对比/透明目标有价值。
2. 如果 A2 提升 AP-thin，说明边缘通道本身有效。
3. 如果 A3 同时提升 AP-small、AP-thin，且 mAP50:95 不下降或轻微下降，则阶段2成立，可以进入阶段3。
4. 如果 A3 不如 A1，说明 Edge 与 PCN 叠加后可能引入噪声，需要检查边缘图质量或考虑减弱 EGI。
5. 如果 A1/A2/A3 都无提升，不建议继续把 PCN/EGI 作为主线，应直接回到 BLT-Mix 或其他数据增强方向。

## 8. 注意事项

1. 训练和预测开关必须一致：
   - A1：训练 `xr_pcn=true`，预测 `xr_pcn=True, xr_egi=False`
   - A2：训练 `xr_egi=true`，预测 `xr_pcn=False, xr_egi=True`
   - A3：训练 `xr_pcn=true, xr_egi=true`，预测 `xr_pcn=True, xr_egi=True`

2. A2/A3 是 4 通道模型，必须从数据 YAML 的 `channels: 4` 构建模型，不要直接拿 3 通道模型结构继续训。

3. 阶段2第一轮建议只跑 YOLOv8n。只有 A3 对 AP-thin 或 AP-small 有明确收益时，再考虑扩展到 YOLOv8s/m/l。

4. 阶段2实验完成后，建议把结果汇总到新的 CSV，例如：

```text
runs/stage2/stage2_summary.csv
```

字段建议包含：

```text
experiment, model, map50, map75, map50_95, ap_small, ap_thin, best_epoch, notes
```

5. 本阶段没有启动 300 epoch 训练，也没有在项目外创建文件。所有修改均在当前项目内完成。
