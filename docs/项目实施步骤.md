我是用 `superpowers:writing-plans` 的思路来拆实施路线。这个项目不应该一上来就“实现所有模块”，而应该按 **统计确认 → 基线 → 最小创新闭环 → 模块递增 → 公共验证 → 论文固化** 推进。

**总体路线**
建议分成 8 个阶段，每个阶段都有明确产物和是否继续的判断标准。

# **阶段 0：冻结实验协议**

目标：避免后面结果出来后再改指标，保证论文可信。

要做：

- 固定数据集版本：SPXray、PIDray、OPIXray。
- 固定训练/验证/测试划分。
- 固定 `AP-small`、`AP-thin`、`Hidden AP`、`Overlap AP` 定义。
- 明确增强策略只用于训练集，val/test 保持原始数据。
- 固定输入尺寸、epoch、optimizer、seed、NMS、batch 规则。

产物：

- `docs/实验协议.md`
- `configs/datasets/*.yaml`
- `scripts/check_dataset_stats.py`

通过标准：

- 每个数据集 train/val/test 数量清楚；
- 每类实例数、bbox 面积分布、长宽比分布都能复现；
- 指标定义写死。

# **阶段 1：SPXray 数据统计与基线**

目标：先知道数据长什么样，再判断提升是否可信。

要做：

- 统计每类实例数、每类图像数。
- 统计 small / medium / large 占比。
- 统计 thin 目标占比。
- 训练原始 YOLOv8n。
- 可选训练 YOLOv8s、YOLO11n 作为横向基线。

产物：

- SPXray 类别分布表；
- bbox area 直方图；
- aspect ratio 分布图；
- YOLOv8n baseline 结果。

通过标准：

- YOLOv8n baseline 能稳定复现；
- 至少跑 3 个 seed 或先跑 1 个 seed 做 pilot；
- 得到后续所有模块对比的基准线。

# **阶段 2：最小创新闭环，PCN + EGI**

目标：先验证“边缘结构比单纯颜色更可靠”这个主张，同时明确 PCN 和 EGI 的独立贡献与组合收益。

根据《模型体系设计方案.md》，最终主链路不是简单的“EGI 单独接到 YOLOv8n”，而是：

```text
RGB pseudo-color image
-> PCN
-> Scharr Edge
-> RGB + Edge 四通道输入
-> 4-channel Stem
-> YOLOv8n
```

因此阶段2的实验顺序建议固定为：

```text
A0: YOLOv8n
A1: YOLOv8n + PCN
A2: YOLOv8n + EGI(raw RGB)      # 诊断消融，不作为最终主链路
A3: YOLOv8n + PCN + EGI         # 主方案，后续模块的基础
```

## 阶段2.1：A0，YOLOv8n

作用：阶段1已完成，作为所有阶段2实验的直接对照。

保持不变：

- 输入仍为 3 通道 RGB；
- 模型仍为原始 YOLOv8n；
- 使用阶段1已经得到的 baseline 指标；
- 后续 A1/A2/A3 的训练参数、数据划分、epoch、batch、seed、optimizer、NMS 都应与 A0 保持一致。

## 阶段2.2：A1，YOLOv8n + PCN

作用：单独验证伪彩归一化是否能降低不同图像、不同伪色映射之间的分布偏移。

需要修改：

- 只改数据预处理，不改网络结构；
- 输入仍为 3 通道；
- 在 dataloader 或 transform 中加入 per-image、per-channel 的 P1/P99 百分位归一化；
- train、val、test、predict 必须使用同一套 PCN；
- 第一层 Conv 不需要改，仍可正常加载 `yolov8n.pt` 的 3 通道预训练权重。

PCN 固定定义：

```text
对每张图像的每个通道 c：
p_low  = P1(I_c)
p_high = P99(I_c)
I'_c = clip((I_c - p_low) / (p_high - p_low + eps), 0, 1)
```

需要记录：

- PCN 前后图像可视化样例；
- PCN 对 mAP50:95、AP-small、AP-thin、Recall-thin 的影响；
- PCN 对伪彩扰动稳定性的影响。

## 阶段2.3：A2，YOLOv8n + EGI(raw RGB)

作用：这是诊断消融，用来回答“边缘图本身是否有用”。它不是《模型体系设计方案.md》中的最终主链路，因为主链路中的 EGI 应基于 PCN 后图像生成。

需要修改：

- 不使用 PCN；
- 直接基于原始 RGB 生成 Scharr Edge；
- dataloader 输出从 3 通道变为 4 通道：`[R, G, B, Edge]`；
- 修改 YOLOv8n 第一层 Conv，使其接受 4 通道输入；
- 训练、验证、预测全部使用 4 通道输入。

EGI(raw RGB) 固定定义：

```text
G = 0.299R + 0.587G + 0.114B
E_x = Scharr_x(G)
E_y = Scharr_y(G)
E = sqrt(E_x^2 + E_y^2)
E' = (E - min(E)) / (max(E) - min(E) + eps)
X = [R, G, B, E']
```

Stem 修改：

```text
原始 YOLOv8n stem: Conv(in_channels=3, out_channels=16, kernel=3, stride=2)
EGI 模型 stem:     Conv(in_channels=4, out_channels=16, kernel=3, stride=2)
```

预训练权重适配：

- RGB 三个通道加载原 `yolov8n.pt` 第一层权重；
- 第 4 个 Edge 通道建议用 RGB 三个通道 kernel 的均值初始化；
- 也可以做零初始化作为补充消融，但主实验建议使用均值初始化；
- 必须在实验记录中写明第 4 通道初始化方式。

需要记录：

- Edge map 可视化样例；
- 4 通道输入是否正常通过 dataloader、model、validator、predictor；
- 与 A0、A1 的指标差异；
- 如果 A2 提升有限，而 A3 提升明显，说明“PCN 后边缘更稳定”的论点更强。

## 阶段2.4：A3，YOLOv8n + PCN + EGI

作用：这是阶段2主方案，也是后续 BLT-Mix、EMA-Lite、AIFI-Lite 的基础输入版本。

需要修改：

- 先执行 PCN；
- 再基于 PCN 后的 RGB 生成 Scharr Edge；
- dataloader 输出 4 通道：`[R_pcn, G_pcn, B_pcn, Edge_pcn]`；
- 修改第一层 Conv 为 4 通道；
- 使用与 A2 一致的第 4 通道权重初始化策略；
- train、val、test、predict 全部走同一套 PCN + EGI 流程。

PCN + EGI 固定数据流：

```text
RGB
-> PCN 得到 RGB_pcn
-> RGB_pcn 转灰度
-> Scharr_x / Scharr_y
-> Edge_pcn
-> concat [RGB_pcn, Edge_pcn]
-> 4-channel YOLOv8n
```

需要记录：

- PCN 后图像和 Edge_pcn 的可视化；
- A3 相对 A0、A1、A2 的 mAP50:95、AP-small、AP-thin、Recall-thin；
- Params、FLOPs、FPS；
- A3 是否能在 AP-small 或 AP-thin 上稳定超过 A0。

## 阶段2统一观察指标

- mAP50；
- mAP50:95；
- AP-small；
- AP-thin；
- Recall-small；
- Recall-thin；
- 伪色扰动 Avg Drop；
- Params；
- FLOPs；
- FPS。

## 阶段2通过标准

- `A3: YOLOv8n + PCN + EGI` 至少在 AP-thin 或 AP-small 上相对 A0 有稳定提升；
- A3 的 mAP50:95 不应明显下降；
- A3 的 FPS 损失应较小；
- 如果 A1 提升、A2 不提升、A3 提升，说明 PCN 是边缘稳定性的关键前提；
- 如果 A2 和 A3 都提升，说明 Scharr 边缘本身有效，PCN 进一步改善稳定性；
- 如果只提升 mAP50、不提升 mAP50:95 或 thin/small，说明阶段2主张偏弱；
- 如果 A3 不如 A1，需要重新检查 Edge 生成、4 通道权重初始化和输入归一化是否引入噪声。

# **阶段 3：BLT-Mix 数据增强闭环**

目标：验证你的数据增强是否真的服务于遮挡/隐藏场景。

实验顺序：

```text
Baseline Aug
+ MixUp
+ Copy-Paste
+ BGM-XR / Mix-Paste-XR
+ BLT-Mix
+ PCN + EGI + BLT-Mix
```

关键要求：

- BLT-Mix 只用于训练集；
- val/test 不增强；
- 保留增强可视化样例；
- 记录增强前后类别分布，避免类别偏移。

重点观察：

- Hard AP
- Hidden AP
- Recall
- AP-small
- AP-thin

通过标准：

- BLT-Mix 相比 Copy-Paste/MixUp 在 Hidden/Hard/Recall 上更好；
- 如果只提升普通 mAP，不提升遮挡指标，BLT-Mix 的论文价值会下降。

# **阶段 4：轻量模块递增，EMA-Lite / AIFI-Lite**

目标：只在最小闭环成立后，再加网络模块。

建议顺序：

```text
YOLOv8n + PCN + EGI + BLT-Mix
+ EMA-Lite
+ AIFI-Lite
```

不要一开始加 P2、损失函数、蒸馏。

重点观察：

- EMA-Lite 是否提升 AP-thin / Hidden AP；
- AIFI-Lite 是否提升 Hidden AP / Heavy AP；
- Params、FLOPs、FPS 是否仍在阈值内。

通过标准：

- 每个模块必须有对应指标提升；
- 如果某模块只涨 0.2% 但明显增加 FLOPs，就不要放进 Lite 主模型。

# **阶段 5：决定 Lite / Plus 版本**

目标：把论文主模型收敛下来。

建议：

```text
Lite = PCN + EGI + EMA-Lite + AIFI-Lite（BLT-Mix 最后再验证）
Plus = PCN + EGI + EMA-Lite + AIFI-Lite + P2-Lite
```

P2-Lite 判断规则：

- AP-small 明显提升，FPS 下降 < 10%：可考虑进 Lite；
- FPS 下降 10%–20%：放 Plus；
- AP-small 提升不明显：删掉。

产物：

- `YOLOv8n-XR-Lite`
- `YOLOv8n-XR-Plus`
- 主模型结构图

# **阶段 6：PIDray / OPIXray 公共验证**

目标：证明不是只在 SPXray 上有效。

PIDray 必做：

- Overall
- Easy
- Hard
- Hidden
- Hidden Recall

OPIXray 必做：

- Overall
- Light / Medium / Heavy 或 OL1 / OL2 / OL3
- Heavy Recall

通过标准：

- PIDray-Hidden 有明显提升；
- OPIXray-Heavy 有明显提升；
- 如果 SPXray 有效但 PIDray/OPIXray 无效，论文主张要收缩成“SPXray 场景有效”，投稿价值下降。

# **阶段 7：鲁棒性、复杂度、部署**

目标：补齐论文可信度。

要做：

- 伪色扰动鲁棒性；
- 遮挡强度扰动；
- 输入分辨率敏感性；
- Params / FLOPs / FPS；
- ONNX / TensorRT FP16 可选。

重点：

- 证明模型不是靠固定伪色映射；
- 证明不是用大计算量换精度；
- 证明轻量实时主张成立。

# **阶段 8：论文材料固化**

目标：把实验结果转成论文结构。

最终至少形成：

- 数据集统计表；
- SPXray 总体结果；
- PIDray Easy/Hard/Hidden；
- OPIXray 遮挡等级结果；
- 主模块逐步消融；
- 输入形式消融；
- 增强方法消融；
- 复杂度/FPS 表；
- 检测可视化；
- 失败案例分析。

# **推荐执行优先级**

最务实的顺序是：

```text
1. SPXray 数据统计
2. YOLOv8n baseline
3. PCN + EGI
4. BLT-Mix
5. PCN + EGI + BLT-Mix
6. EMA-Lite / AIFI-Lite
7. Lite / Plus 定型
8. PIDray 验证
9. OPIXray 验证
10. 鲁棒性 + 速度 + 可视化
```

我的建议是先把前 5 步当成第一阶段项目。只要 `PCN + EGI + BLT-Mix` 在 SPXray 上能稳定提升 `mAP50:95 / AP-small / AP-thin / Recall`，再进入复杂模块和公共数据集验证。这样推进风险最低，也最容易及时止损。
